# sage-receipts: verifier for SAGE outcome receipts (v1)

Status: **built 2026-11-01, off-consensus.** No receipts from a real pilot have been verified yet.

[SAGE](https://github.com/l33tdawg/sage) governs what AI agents remember. Its outcome receipts
(`sage.noesis.outcome-receipt/v1`, design doc `docs/design/noesis-outcome-receipts.md`, reference code
`internal/outcomereceipt`) record whether one public memory changed task outcomes: paired control and
treatment runs under a pinned judge, where the treatment context is the control context plus that one
memory, signed with Ed25519 by an evaluator. This crate checks a receipt the way SAGE's own code does
(computing the same canonical bytes and digest, and stricter in four documented places, below) and turns
a valid one into a label Noesis can use as outside evidence: for the calibration measure
(do today's valuations predict independent use later?) and for the learned judge. It came out of the
first outside contribution to Noesis, [issue #2](https://github.com/WGlynn/noesis/issues/2).

**Off-consensus by construction.** Nothing in `node` depends on this crate, so a receipt cannot reach
standing or finality. That matches the fence in ARCHITECTURE.md (the value layer never touches finality)
and SAGE's own rule that no authority flows either way.

## Run

```bash
cargo run -p sage-receipts --bin sage-receipt-verify -- receipt.json --labels data/receipts/labels.jsonl
```

Prints the verdict as JSON. Exit 0 = valid (the label is appended once; a digest already in the file is
not written again), 1 = invalid (with the first broken rule), 2 = usage or I/O error.

## What is checked

Everything SAGE's `Decode` and `VerifyEnvelope` check: strict JSON (no duplicate keys, nesting at most 64,
no unknown fields, nothing after the value); every field rule (lowercase SHA-256 hex, ASCII identifiers,
NFC text without control characters, canonical decimals, UTC timestamps written with `Z`); the
counterfactual pairing (one control and one treatment per task and trial, the same query and seed,
treatment context equal to control context plus the candidate, control masking the candidate); the
summary (pair count, required values unless `failed`); the task-set digest; and every signature over
`version || 0x00 || SHA-256(canonical body)`, with at least one evaluator signature and no duplicates.

## Parity with the reference

`tests/vectors/sage-ae7f8a7.json` holds 40 cases generated by SAGE's own Go code (commit `ae7f8a7`,
Go 1.26.10): the exact input, SAGE's verdict, and for accepted cases its digest, canonical bytes and
task-set digest. The test requires the same verdict, digest and bytes for every case. To regenerate,
copy `tests/vectors/zz_noesis_vectors_test.go` into SAGE's `internal/outcomereceipt/` and run
`NOESIS_VECTORS_OUT=<path> go test ./internal/outcomereceipt -run TestDumpNoesisVectors`. It includes SAGE's
golden digest for its own fixture (`84d86024...9f0d54`), escaping edge cases, fractional and oddly
written timestamps, maximum integers, unsorted sets, three signers and a self-evaluation (12 accepted
cases), and 28 rejected ones.

Deliberately stricter than the reference, each failing closed (a receipt written by SAGE's tooling uses
none of these): object keys must match exactly (Go matches them case-insensitively; this one is pinned as
the only allowed mismatch in the vectors); JSON `null` is rejected where a value is expected; invalid
UTF-8 and lone surrogates are rejected; signatures use `verify_strict`, which also refuses small-order keys.

**A quirk kept for parity (not yet raised with SAGE):** SAGE's negative-zero rule rejects any decimal
starting with `-0.`, so every negative value between -1 and 0 fails (`delta "-0.25"`, `ci95_lower "-0.1"`).
For a pass-rate metric that rules out recording a negative effect smaller than a whole point, or an
interval that crosses zero. Two vectors pin the current behavior; this crate changes when the reference does.

## The label, and what it does not prove

A label carries the receipt digest, the candidate, the task set, the metric and its values (decimal
strings, exactly as signed), the judge, the producer, the signers, and independence facts: whether an
evaluator key is the candidate's or a task's author key. A valid receipt proves that the named key signed
these numbers. It does not prove the evaluator is independent of the memory's author, that the task set is
honest, or that the judge is good: SAGE's design leaves those to the consumer, and Noesis has no written
evaluator policy or honest task source yet (both open in ARCHITECTURE.md).

## Open gaps

- No trusted-evaluator policy: the label records independence facts; nothing decides on them yet.
- NFC is checked with the `unicode-normalization` crate, SAGE with Go's `x/text`; the two Unicode versions
  may disagree on characters assigned after the older one. Not covered by a vector.
- v1 only: coalition receipts (v2, for Shapley over the measured coalition function) are designed upstream,
  not here.
