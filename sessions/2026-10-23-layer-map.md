# Session recap: 2026-10-23, the layer map

Plain-English recap. Reading artifact, not an operator handoff.

## What we did
Wrote `docs/DESIGN-layer-map.md` (proposed, nothing built). It splits the system into five layers by one
rule: where rivalry starts. Records and the non-rival facts they share merge by plain union with no one
in charge. Rival things (money, finality, two people claiming the same work) are settled by the parties
who share them. Worth is computed on top, and money stays per chain. For each layer it names what is
built, what isn't, and what Holochain, Scuttlebutt, Ceramic and Nostr already got wrong there. It also
lists six things any chain has to record to join the network as a peer (most of them aren't built yet,
even in Noesis), and maps the day-30 devnet bar agreed with Boardy onto the layers it tests.

## What we found
- **A copy is not free under Shapley.** The coalition idea said Shapley pays a copy nothing. Under a
  value rule that looks only at outcomes, an exact copy is worth as much alone as the original, so
  Shapley splits it in half. A copy earns zero only once an access test rules it a copy: its content
  was public before the copier committed. So timestamps still matter, as evidence of who could have
  copied whom, even though first commit pays nobody. The 10-22 research note now carries this
  correction.
- **The equal split needs no value oracle.** Today the code only flags exact duplicates, and for exact
  duplicates the Shapley split is equal whatever the value rule is. So coalition resolution for that case
  could be built before the value layer exists.
- **The built standing rule is first-commit-wins.** Temporal novelty pays the earliest cell in commit
  order. That is right for stopping padding, but it has no meaning across chains (there is no shared
  order). Inside one chain, two people who commit the same work in the same block get their standing
  decided by the shuffle. Whether standing should split like value is a question for Will.

## Then: day 3 of the devnet bar
Boardy's day-3 post set the bar: two nodes on two machines, only talking over the network, and the wire
trace replayed in shuffled orders from a public seed list, every run ending on the same hash. The
starting point was one node plus a test that merges with a function call.

Built today: `factnode` (`node/src/bin/factnode.rs` over `node/src/factsync.rs`). Two separate processes
share nothing but a TCP connection. Each sends its contribution facts, receives the other's, and prints
the merged hash. Both ends print the same one. Each saves a trace of what it applied, and `factnode replay`
reruns that trace once per seed in `docs/devnet/shuffle-seeds.txt` (the integers 1 to 64, fixed in
advance). On both traces, all 65 runs (trace order plus 64 seeds) landed on the same hash. A peer started with `--junk` also sends a repeated record, a
record claiming someone else's id under a different key, a cut-off frame, an unknown frame and an empty
one. The other side accepts the repeat and rejects the other four wherever they land in the order. A test
runs all of this as real processes (`node/tests/factnode_two_process.rs`).

Floor: both processes ran on one machine over loopback (the code is the same with a real address). The
agreement holds by construction (a union, with each frame judged on its own), so the 64 seeds guard
against a future change that makes order matter rather than proving something new. The demo chains are
tiny. Records carry no signatures yet, so a record forged under someone else's key would still get in.

## Then: signatures, and Boardy's forgery-first test
Records now carry their author's signature. The author signs the record's content id, which covers who
wrote it, what it says and what it builds on. A receiver accepts a record only if the id matches its
contents and the signature checks out. Boardy's case is covered: a forged copy of a real record arrives
first and is rejected, then the real one arrives and is accepted, because a rejection leaves nothing
behind. The junk test now sends seven bad messages ahead of the real records, among them that forged
copy and a record putting words in the author's mouth. All seven are rejected in every shuffled order,
and the hash still matches on both ends.

Floor: only the demo chains can sign. Their keys come from public names. The live chain throws the
wallet's signature away after checking it, and the wallet signs its contribution, not the content id
(so not the parent). Each signed record is about 16.8 KB, almost all of it the signature.
